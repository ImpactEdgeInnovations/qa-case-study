Regression and API results

Regression scope for v1.1: all 9 test cases, because the fixes touched balance, transfer and history logic, which every journey depends on.

API suite: 5 checks on the API page: status codes, required fields, a not-found case and a create (POST) case.

Release sign-off: v1.1

Recommendation: Approved for release.

All 4 defects are fixed and verified. 9 of 9 test cases pass on v1.1. No open critical or high defects. Evidence: this dashboard, defect log and screenshots in the evidence folder.

Integration results (INT-01 to INT-06, DEF-05 to DEF-07) are on the Integration page. All three integration defects are also fixed and verified in v1.1.

Residual risk: the app is a demo with no real backend, so performance, security and real device-network behaviour are not covered.

Quality improvement

  • Pattern: 2 of 4 defects were calculation or balance errors. Add a calculation check to every money-moving test case.
  • Pattern: error messages were unclear. Add an error-message review to the test checklist.
  • Coverage gap: no tests for session timeout, duplicate submissions or slow networks. Add these next.
  • Automation idea: the regression suite is repeatable, so it is a good candidate for automation (for example Playwright).
